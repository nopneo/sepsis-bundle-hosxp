# ข้อกำหนด: หน้าต่างเตือนสงสัย Sepsis หลังบันทึกสัญญาณชีพใน KIPS

**ผู้ขอ:** โรงพยาบาลวังน้ำเขียว · **ถึง:** ทีมพัฒนา KIPS / IPD Paperless · **ฉบับ:** 1.0 (27 ต.ค. 2569)

## 1. ความต้องการ

เมื่อพยาบาลหอผู้ป่วยบันทึกสัญญาณชีพ (หน้าบันทึกปรอท / Nurse Note ที่เก็บลง `ipd_nurse_note`)
และค่าที่บันทึก **เข้าเกณฑ์สงสัย Sepsis** ให้ KIPS แสดงหน้าต่างเตือนทันทีบนหน้าจอที่บันทึก

ที่ ER โรงพยาบาลใช้เกณฑ์นี้อยู่แล้วผ่าน script หน้าซักประวัติของ HOSxP แต่ KIPS ไม่มีจุดให้โรงพยาบาลใส่ script เอง
จึงขอให้ทีมพัฒนาเพิ่มในหน้าบันทึกปรอทของ KIPS

## 2. เกณฑ์การเตือน

เตือนเมื่อครบ **ทั้ง 3 ข้อ**

1. ผู้ป่วยอายุ **≥ 15 ปี** (เด็กใช้ฟอร์ม PEWS ของ KIPS อยู่แล้ว)
2. **SOS Score > 3**
3. **ไข้ T ≥ 38 °C** หรือ **ตัวเย็น 20 < T < 36 °C**

### ตารางคะแนน SOS (4 ค่า รวม 0–11)

| ค่า | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| อุณหภูมิ T (°C) | 36.1–38.0 | 35.1–36.0, 38.1–38.4 | ≤ 35.0, ≥ 38.5 | – |
| SBP (mmHg) | 101–180 | 91–100, 181–199 | 81–90, ≥ 200 | ≤ 80 |
| ชีพจร (/min) | 51–100 | 41–50, 101–120 | 121–139 | ≤ 40, ≥ 140 |
| RR (/min) | 9–20 | 21–25 | 26–35 | ≤ 8, ≥ 36 |

### กติกาที่ต้องตรงกับระบบเดิม (สำคัญ)

ต้องให้ผลตรงกับหน้าต่างเตือนของ ER **ทุกค่า** แนะนำให้ใช้ `sos_alert.js` ตามที่ให้ไปเลย
หรือถ้าเขียนใหม่ ให้ผ่านชุดทดสอบ `test_vectors.json` ครบทั้ง 54 กรณี

- **ค่าว่าง / 0 / ค่าผิดได้ 0 คะแนน** ไม่ใช่คะแนนสูงสุด: T ≤ 20, SBP ≤ 50, ชีพจร ≤ 20, RR ≤ 2
- ชีพจร 100 ได้ **0** และ RR 35 ได้ **2** เพราะสูตรเดิมตรวจช่วงล่างก่อน
- T ที่อยู่ระหว่างช่วง เช่น 36.05 หรือ 38.45 ได้ **0** ตามสูตรเดิม (บันทึกจริงมีทศนิยมหลักเดียว จึงแทบไม่เกิด)
- T 36.0 ได้ 1 คะแนน แต่**ไม่**นับเป็นตัวเย็น (ต้องต่ำกว่า 36)
- ค่าใดไม่ได้กรอก ให้คิดจากค่าที่มี และยังเตือนได้ถ้าเข้าเกณฑ์

## 3. ข้อมูลที่ใช้ (`ipd_nurse_note`)

| ใช้เป็น | คอลัมน์ |
|---|---|
| T | `temperature` |
| SBP / DBP | `bp_systolic` / `bp_diastolic` |
| ชีพจร | `pulse` ถ้าว่างใช้ `heart_rate` |
| RR | `respiratory_rate` |
| อายุ | `an_stat.age_y` (หรือที่หน้าจอมีอยู่แล้ว) |

คำนวณจาก**ค่าที่อยู่บนหน้าจอขณะกดบันทึก** ไม่ต้องอ่านฐานข้อมูลซ้ำ

## 4. พฤติกรรมหน้าจอ

1. พยาบาลกด **บันทึก** → บันทึกลงฐานข้อมูลตามปกติก่อน (**การเตือนต้องไม่ขัดขวางการบันทึก**)
2. ถ้าเข้าเกณฑ์ → แสดงหน้าต่างเตือน (modal สีแดง) ทับหน้าจอ เนื้อหาได้จาก `alertMessage()` ใน `sos_alert.js`:

   ```
   เตือนสงสัย SEPSIS (หอผู้ป่วย)
   SOS Score = 8 (T 2 · BP 2 · HR 2 · RR 2)
   มีไข้ T 39.2 °C
   BP 82/50  HR 128  RR 28

   1. แจ้งแพทย์ประเมินทันที
   2. ประเมินแหล่งติดเชื้อ · สงสัย Sepsis → เริ่ม Sepsis Six ภายใน 1 ชม.
   3. วัดสัญญาณชีพซ้ำถี่ขึ้น · ติดตาม SpO2 / Urine Output
   ```

3. ปุ่ม **[รับทราบ — แจ้งแพทย์แล้ว]** และ **[รับทราบ]** ต้องกดปุ่มใดปุ่มหนึ่งจึงปิดหน้าต่างได้
4. เตือนทุกครั้งที่บันทึกแล้วเข้าเกณฑ์ ไม่ต้องจำว่าเคยเตือนแล้วหรือยัง เพราะเตือนตอนพยาบาลอยู่หน้าเครื่อง
5. ผู้ป่วยที่ไม่เข้าเกณฑ์ ไม่มีอะไรเปลี่ยนจากเดิม

## 5. สิ่งที่ขอให้บันทึกเพิ่ม (ถ้าทำได้)

1. **เขียนคะแนนลง `ipd_nurse_note.sos_score`** ทุกครั้งที่บันทึก ไม่ว่าจะเข้าเกณฑ์หรือไม่
   (คอลัมน์มีอยู่แล้วแต่ยังว่าง) เพื่อใช้ทำรายงานและแสดงในกราฟปรอท
2. **เก็บประวัติการรับทราบ** เช่นตารางใหม่ (ชื่อและรูปแบบให้ทีมพัฒนากำหนด):

   | คอลัมน์ | ตัวอย่าง |
   |---|---|
   | `nurse_note_id`, `an` | อ้างถึงแถวที่บันทึก |
   | `sos_score` | 8 |
   | `alert_datetime` | เวลาที่แสดงหน้าต่าง |
   | `ack_staff`, `ack_datetime` | ผู้กดรับทราบและเวลา |
   | `ack_type` | `DOCTOR_NOTIFIED` / `ACK` |

   ใช้ตรวจสอบภายหลังว่าเตือนแล้วแจ้งแพทย์ภายในกี่นาที (ตัวชี้วัดคุณภาพ Sepsis)

## 6. การตั้งค่า (`kips_sys_var`)

| `sys_name` | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `kips_sepsis_alert_enable` | `Y` | เปิด/ปิดการเตือน |
| `kips_sepsis_alert_sos_gt` | `3` | เตือนเมื่อ SOS **มากกว่า** ค่านี้ (`opts.sosGreaterThan`) |
| `kips_sepsis_alert_min_age` | `15` | อายุขั้นต่ำ (ปี) (`opts.minAgeYears`) |

ชื่อคีย์เป็นข้อเสนอ ปรับให้ตรงกับแบบแผนของ KIPS ได้

## 7. ไฟล์ในชุดนี้

| ไฟล์ | ใช้ทำอะไร |
|---|---|
| `README.md` | เอกสารนี้ |
| `sos_alert.js` | โค้ดต้นแบบ ไม่มี dependency ใช้ได้ทั้งเบราว์เซอร์ (`window.WnkSosAlert`) และ Node.js (`require`) |
| `test_vectors.json` | ค่าที่ป้อนและผลที่ต้องได้ 54 กรณี รวมค่าตรงขอบทุกช่วง |
| `test_sos_alert.js` | ตัวรันทดสอบ: `node test_sos_alert.js` → ต้องได้ `54/54 กรณีผ่าน` |

ตัวอย่างใช้งานในหน้าบันทึก:

```js
const r = WnkSosAlert.evaluate(
  { temp: form.temperature, sbp: form.bp_systolic, dbp: form.bp_diastolic,
    pulse: form.pulse || form.heart_rate, rr: form.respiratory_rate, age_y: patient.age_y },
  { sosGreaterThan: sysVar.kips_sepsis_alert_sos_gt, minAgeYears: sysVar.kips_sepsis_alert_min_age });
// บันทึก r.sos ลง ipd_nurse_note.sos_score
if (r.alert) showSepsisModal(WnkSosAlert.alertMessage(form, r));
```

`test_vectors.json` ตรวจแล้วว่าตรงกับสูตร SQL ที่ใช้งานจริงในหน้าต่างเตือน HOSxP ของ ER
(รันบน MariaDB ทุกกรณี ผลตรงกัน 54/54)

## 8. ปริมาณการเตือนที่คาดไว้

จำลองจาก `ipd_nurse_note` จริง 30 วัน (ผู้ใหญ่ 4,540 ครั้งที่บันทึก):

- เข้าเกณฑ์ **135 ครั้ง** จากผู้ป่วย 47 ราย ≈ **4–5 ครั้ง/วัน** ทั้งโรงพยาบาล
  (นับผู้ป่วยละไม่เกินวันละครั้ง ≈ 2.8 ครั้ง/วัน)
- ผู้ป่วยในที่ได้วินิจฉัย Sepsis ช่วงเดียวกัน 11 ราย มี 6 รายที่เข้าเกณฑ์ระหว่างนอนหอ

## 9. ความเป็นส่วนตัว

การคำนวณและการเตือนทั้งหมดอยู่ใน KIPS และฐานข้อมูลของโรงพยาบาล **ไม่ต้องส่งข้อมูลออกนอกระบบ**
ไฟล์ในชุดนี้ไม่มีข้อมูลผู้ป่วยจริง ค่าในชุดทดสอบเป็นค่าสมมติทั้งหมด
